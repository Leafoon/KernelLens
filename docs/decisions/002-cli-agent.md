# ADR 002 — 工作区内的终端 Agent

- 日期：2026-09-12
- 状态：已实现；MiMo 真实工具流程验收通过，算子内容及硬件边界见 [验收记录](../validation.md)。

## 背景

产品需要可运行的 CLI：启动选择工作区，在该工作区连续交互，覆盖生成、优化和诊断，并具备配置、错误处理和运行说明。实现沿用已有领域模型与 Runtime，并补齐模型接入、工具、会话和交付审核。

## 决策

使用单进程、单 Agent。`cli.main` 负责输入与显示，`AgentApplication` 装配配置、会话、模型、工具与审核，已有 `run_agent` 负责有界行动循环。模型提出行动；路径限制、实际写入、停止条件和检查结论由程序决定。

不引入额外运行服务或 Agent 框架。HTTP、SQLite、AST 和 CLI 使用 Python 3.12 标准库；Pydantic 同时生成工具 Schema 并验证实际输入。入口既支持连续终端交互，也支持单次 JSON 输出。

### 模型与控制流

兼容 Chat Completions 原生工具协议，保留 call ID 与工具结果的配对；可显式选 JSON 行动模式。不兼容的多工具提议整批拒绝，错误反馈计入同一决策预算。超时和有限重试属于 HTTP 层，不能把 HTTP 请求数等同于决策数或账单用量。

Runtime 新增 `on_step` 与 `on_rejection` 回调。已有调用者不传回调时保留原行为；正式应用将步骤即时保存，并在交付审核拒绝后反馈给模型，让其在剩余预算内修正。状态 completed 只表示程序交付门槛通过。

### 工作区、持久化与继续

工作区是工具文件访问根，配置在启动时加载，切换目录不隐式更换 Key。工具读取与写入限制目录、类型、大小及敏感路径；覆盖使用 SHA-256 比对、备份和原子替换。没有任意 shell/代码执行工具。

SQLite 按工作区保存 sessions、messages、runs、steps。每步提交，一轮结束保存 Markdown 报告和 JSON 清单。缺少信息时停止为 waiting_input；补充信息或显式重试创建新 run，携带原目标和近期会话，重新读取文件。不会重放历史写入或恢复旧请求的中间状态。退出后可用唯一 ID 前缀恢复会话。

### 验收与证据

生成和优化必须保存 Python 候选，并对当前哈希完成 AST 语法检查；优化还必须读取不同版本的 baseline。模型答案引用的 E 编号必须属于当前运行。辅助 Python 脚本同样需要语法检查，但不要求自身声明 GEMM。

真实生成样本曾把要求的 C float16 写成 float32，却通过 AST。这促使加入独立的静态 GEMM 声明检查：对可识别的常量、默认值和 Tensor 声明核对 shape/dtype；未知表达式不当作通过。优化从可识别的 baseline 继承约束。该分析是有限声明检查，不是 Python 类型检查器、TileLang API 验证器或正确性证明。

服务器报告保留 `user_report` 来源；关联候选哈希，对比前核对相同环境、workload、测量方式、正确性状态和重复样本。中位数比值只描述报告中的数据。无 GPU 执行证据时，不报告正确性或性能改善。

## 影响和边界

- CLI 不依赖本地 GPU；Mac 可完成 Agent 工程，算子硬件验证由服务器承担。
- 本决策初版交付时没有有效 TileLang 源码与知识库，旧算子不宣称 API 已核对。后续已按 [结构化 RAG 决策](003-tilelang-rag.md) 增加源码知识库；硬件验证仍独立进行。
- 本地自动测试与 localhost HTTP 测试可独立验证 Agent；真实云端质量和服务可用性必须单独验收。
- 旧领域层的 VerificationState 保持原契约，应用层记录具体文件检查和证据；模型文本不能直接修改 GPU 验证状态。
- 工作区工具不是抵御恶意本机并发进程的操作系统沙箱；配置中的 Token 门槛也不是供应商费用硬限制。
