# ADR 003：TileLang 语义单元与分层检索

状态：已实现；分发方式由 [ADR 004](004-bundled-knowledge.md) 补充，普通用户默认使用随包快照。验收记录随 公开状态说明 更新。日期：2026-09-13。

## 问题

普通文件子串搜索无法稳定区分 DSL API、kernel 示例和编译器实现，也不能识别方言导出关系。直接把仓库所有内容混入上下文会扩大噪声和请求成本。

## 决策

先按 AST 函数/类、文档语义小节、完整 kernel 构造函数和 C++ 命名声明抽取单元，再建立五类 SQLite FTS5 索引。每个单元带源码位置、版本、哈希、别名、可见性和关系。保留公开导出链，使用有界不动点传播处理循环和覆盖。

问题路由选择 API / Concept / Example / Compiler / Operator，有限候选排序后返回 Top-K 和受字符预算限制的材料。完整知识保存与模型上下文传输分开；长单元分页读取，显式显示截断。

应用配置一个只读知识库路径，独立于任务工作区。程序预检索保存在 decision 0；模型的两种知识工具沿用现有 E 证据和运行记录。生成/优化需要完整参考阅读，候选增加有限公开导出/关键字检查。

知识库生成在独立 TileLang 克隆内，可重建，不加入外层 Git。MCP 兼容层从同一批单元派生；KernelLens 使用自己的有界查询策略，不依赖 MCP 的排序质量来控制 Prompt。

## 代价与边界

不引入 embedding 或数据库服务，部署沿用标准库；代价是词法检索依赖领域词表和查询表达。C++ 扫描不是完整语义解析，动态或外部 API 可能没有定义。回归集证明已测问题的结果与预算，不能保证任意扩库后的全局相关性。

RAG 不替代 TileLang 编译、数值或性能验证。现有源码版本只为这个构建提供依据，源码变化后需重建。实现与运行方法见 [详细说明](../tilelang-rag.md) 和 [计划](003-tilelang-rag.md)。
