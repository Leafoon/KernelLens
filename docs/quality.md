# 测试、评测、可观测性与风险

> 历史设计与学习讲义：文中的阶段进度、测试数量和旧提交号不代表当前版本。当前能力见 [状态说明](status.md)，参与开发见 [贡献指南](../CONTRIBUTING.md)。

本文定义质量策略，尚无测量结果。所有量化收益必须来自实际测试。阶段与任务映射见 [roadmap.md](roadmap.md) 和 [backlog.md](backlog.md)。

## 两种质量判断

Runtime 内的 Report Verifier 检查当前报告是否满足需求、引用与验证声明的契约。
Offline Evaluator 衡量一组任务的质量、失败、延迟和成本。二者不能用一个“模型说成功”的字段替代。

## 测试分层

| 层次 | 检查内容 | 运行方式 |
| --- | --- | --- |
| 文档与工程 | 文件、链接、图源同步、Git Root、环境 | 无模型调用 |
| Unit | 状态转移、Schema、预算、评分公式、路径边界 | FakeModel 与明确断言 |
| Integration | 工具循环、证据检索、状态保存、API 与恢复 | 默认本地替身或固定材料 |
| Provider Contract | 工具参数、call ID、结构化响应与 usage | 确认模型和预算后显式启用 |
| Offline Evaluation | 生成、优化、诊断与信息不足场景的语义质量 | 固定版本、保留原始记录、控制预算 |
| Hardware | 编译、正确性、性能与资源使用 | 对应服务器；与 Mac 静态检查分开 |

MVP 从第一轮 Runtime 开始记录步骤和资源；恢复、服务负载及执行器检查随能力引入。不给低影响文档改动创建镜像实现的单元测试。

## 案例集设计

先人工走查生成、优化、诊断各两个代表案例，作为开发素材；MVP 评测阶段计划扩展到至少 20 个经审核案例，覆盖信息不足、未知设备、失效证据和故障路径。这是工作目标，不是已存在的数据集。

每个案例记录：ID、任务类别、用户输入、源码与材料版本、期望行为、关键证据、允许的工具集合／有效路径、评分规则、执行条件与来源。

维护开发集与保留评测集；不要把评分答案放入检索材料。区分人工、合成、记录回放与真实运行案例。保留重复运行的离散程度；失败后重跑不能覆盖原始失败记录。

生成案例检查计算契约和证据覆盖；服务器可用时增加实际编译与数值结果。优化案例需要合理且可检验的假设，性能改善另用真实测量验证。诊断案例允许多条有效调查路径，不强迫唯一工具顺序。

## Baseline 与优化实验

对比：给定材料单次 LLM；固定检索／检查 Workflow；动态 Agent。固定案例、模型标识、工具权限和可比较资源条件；报告无法保持一致的条件。

任何优化先写假设与预期影响，尽量一次改变一个变量。使用保留集复测，报告质量、延迟、成本和失败类型的共同变化。固定 Workflow 更合适的任务无需强行走 Agent。

## 指标口径

| 指标 | 定义与注意事项 |
| --- | --- |
| Task Success Rate | 达到案例任务契约的比例；按生成／优化／诊断分别统计 |
| Tool Selection Accuracy | 有标注决策点中，所选工具属于合理集合的比例；允许多种有效路径 |
| Tool Execution Success Rate | 合法调用中工具正常完成执行的比例；工具报告“编译失败”仍可能是执行成功 |
| Answer Quality | 正确性、需求覆盖、证据、可操作性、不确定性表达分别评分 |
| Hallucination Rate | 经人工或受审核评分确认的无证据可核验断言占比；明确标为假设的内容单列 |
| Latency | 端到端及步骤耗时；样本足够时报告中位数与高分位数，注明样本数 |
| Token Consumption | provider 实际 usage，区分输入、输出和可得的其他类别；缺失为 unknown |
| Cost | 依据版本化价格规则与实际 usage 计算，标明估算范围；不能拿零代替缺失数据 |
| Retry Rate | 重试调用数与原始调用数，并按原因分组；纠正参数与网络重试分开 |
| Failure Rate | 按模型、工具、环境、输入、预算、恢复等分类统计终止任务 |

信息不足案例中，正确请求补充可算成功；同时报告回答覆盖率和正确拒绝率，防止全部拒答刷分。工具调用成功率不替代业务成功率。

LLM-as-judge 如引入，仅作为经过人工样本校验的辅助评分器；记录版本、rubric 和与人工分歧。程序可直接判断的引用与状态不交给模型投票。

## 性能结果有效性

- 对照使用相同计算语义、shape、dtype、布局、容差与可比较环境。
- 保存候选和 baseline 的代码标识、设备、源码／编译环境、测量方法、预热与重复信息。
- 单个延迟数不自动证明改善；样本数量和噪声处理在实际实验阶段确定。
- hash、环境或工作负载不匹配时，不能把记录作为当前候选的验收证据。
- 人工提供的日志保留原始来源；没有执行器证明时不宣称 Agent 亲自运行。

## Observability

MVP 每一步记录 run_id、step、行动类型与简短理由、tool/version、参数摘要、Observation 引用、状态变化、耗时、错误、重试和 usage。完整源码与日志保存在受限产物中，轨迹默认使用摘要和引用。

V1 提供查询与取消／恢复过程视图，并按需要导出追踪。计划日志记录可审计的行动摘要，不要求保存或伪造模型内部思维链。记录中不得包含 API 密钥；源码和错误日志的敏感数据需要限制或脱敏。

## 风险与处理

| 风险 | 控制方式 | 验证方式 |
| --- | --- | --- |
| Infinite Agent Loop | 全局步数、时间、token 和费用预算；无进展／重复动作检测 | 固定循环 FakeModel 必须退出；Verifier 回路也计入预算 |
| Planner Failure | 有限 Action 类型；记录缺口；不能修改用户目标 | 非法行动与目标漂移案例 |
| Wrong Tool | Registry 与当前权限共同决定可调用集合 | 未知／未授权工具被拒绝且可观察 |
| Wrong Arguments | Schema、参数边界与明确错误 Observation | 类型错误、越界和缺字段案例 |
| Hallucination | 证据标识、API 逐项确认、报告关卡 | 伪造 API、缺失源码、错误引用案例 |
| Context Explosion | 限制片段和输出；存储完整材料；受限上下文 | 大日志与多次检索不会无限增长 |
| Context Pollution | 分离指令与材料；源码／日志不能授权新操作 | 材料中嵌入诱导指令的负例 |
| Memory Pollution | 未确认假设不晋升事实；历史案例带版本与纠错机制 | 错误结论与过期案例不会静默复用 |
| RAG Failure | 精确符号、元数据、召回评测与缺口报告 | 中英文、别名、缺失与过期记录 |
| Model Instability | 记录模型／Prompt 版本，重复评测保留离散性 | 同案例多次运行及回归 |
| Structured Output Failure | 校验、有限纠正、明确失败；不无限修复 JSON | 截断、非法结构、缺失字段 |
| Token Cost | 调用前检查预算，调用后记账；未知 usage 显式处理 | 临界预算与多层重试案例 |
| High Latency | 分步骤测量；超时与取消；只并发独立只读操作 | 超时传播与瓶颈归因 |
| External API Failure | 分类错误；有限退避；避免 SDK 与应用重试相乘 | 429、认证错误、网络断开等注入 |
| 恢复与副作用 | 操作标识、状态核对、有限重放；不能安全重放则停止 | 写入后断线、重复请求、版本变化 |
| 用户代码执行 | MVP 不 import/eval/exec 用户代码；后续隔离环境执行 | 路径逃逸、资源限制、超时与网络权限测试 |

重试预算必须覆盖全部尝试；认证错误等不可通过重试解决的情况直接报告。模型调用前预算检查不能保证 provider 账单绝对不超出估计，因此需预留最大输出和重试空间，并标注估算。

## 版本化与交付验收

Prompt 与 Tool Schema 的重要变化通过 Git 追踪并在 run 中记录版本；源码证据固定 revision 和内容标识。模型、输入案例、评分规则、价格规则和运行环境随评测报告保存。

发布前要求确定性关键不变量全部通过，真实语义结果有报告，未完成的硬件验证明确列出。准确率和延迟门槛在首轮基线后依据业务需要确定，不预先编造改善百分比。

简历与面试材料最终依据真实代码和报告编写：问题 → 设计 → 实现 → 失败与定位 → 实验 → 结果。普通 CRUD 与配置不包装成核心 Agent 创新。
