## 知识包与检索

内置快照包含来自 856 个文件的 4,337 个语义单元：API 1,148、instruction 134、concept 215、example 240、operator 107、compiler 2,493。五张检索索引存在交叉归属，索引行数不等于独立单元数。

公开回归集位于 `knowledge/evaluation_queries.json`，当前 **28/28** 通过，覆盖精确符号、双语概念、API facade、未知符号、基本算子、目标后端、编译器、完整长需求与上下文预算。

```bash
uv run --locked python -m kernellens.knowledge validate
uv run --locked python scripts/evaluate_knowledge.py
```

这是开发中公开调整的回归集，不是盲测集或通用问答准确率。测试还覆盖分页、过期来源、损坏包、候选上限、扩库噪声、工具 JSON 大小和首次预检索。

## 独立分发

普通用户使用 snapshot 模式：SQLite 保存完整正文和索引，不读取外部 TileLang 源文件；原路径、行号和哈希是出处。维护者 source 模式继续检查源文件变化。

已有测试验证原源码删除后仍能查询、全文阅读与检查 API。早期 wheel 独立安装验收还禁止访问原项目源码和网络，验证 28 条查询、阅读、API 检查和两次替身模型请求。内置包保留上游 LICENSE 与 THIRDPARTYNOTICES，不重复包含旧 MCP JSONL 视图。

## 真实工作流暴露的问题

- 基础 GEMM 的长需求曾召回不相关的稀疏/调优变体，促成问题路由、基本示例排序和长需求回归。
- 示例中的动态尺寸不能作为固定 shape 的证明，检查器与提示词对此保留边界。
- 模型曾遗漏新分配 fragment 的清零；有限初始化检查现会拒绝能确定的遗漏，复杂控制流仍可能是 inconclusive。
- 模型报告曾过度声称 API 全部验证，以及给出缺少依据的运行建议。源码引用和静态门槛无法证明每句自然语言都正确。
- 优化会占用更多上下文与模型预算；默认配置不保证任意任务在一次运行中完成。

这些问题被保留为测试和明确限制，原始会话与私人验收产物不随仓库上传。

## GPU 与静态检查

GPU 型号进入模型上下文和检索查询。预检索及后续查询默认按已知后端过滤，未标注目标的通用知识仍可返回；这不是 SM 架构或指令兼容性验证。

有限 API 检查核对公开导出和关键字名，不验证所有位置参数、类型或 lowering。动态/外部包装签名可能无法静态确定；初始化检查也不是完整控制流证明。

没有执行真实 GPU 编译、数值对比和性能计时。候选必须在匹配服务器上独立验证，不能把检索成功或静态检查通过作为硬件结果。
