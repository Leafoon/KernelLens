# KernelLens 终端界面

这是运行在终端中的本地工作台。使用 Textual 绘制对话、输入框和面板，复用现有 AgentApplication；无需浏览器、Web 服务或额外前端构建。

## 启动

```bash
uv sync --locked
uv run --locked kernellens --tui -w /path/to/workspace
```

目录需已存在。模型配置沿用 `.env` 或环境变量，见 [CLI 手册](cli.md)。已有 `.env` 无需重写。

正常交互终端中，直接运行 `uv run --locked kernellens` 也会默认进入 TUI，工作区为启动目录。用 Ctrl+O 或 `/workspace 路径` 切换。推荐至少 80 列 × 24 行，100 列以上显示侧栏。支持 UTF-8 和 ANSI 的现代终端；当前实测 macOS ARM64，其他平台尚未完成同等验证。设置 `NO_COLOR` 的终端会采用无彩色显示。

```bash
# 保留原来的逐行提示符和 Ctrl+C 中断方式
uv run --locked kernellens --plain

# 单次任务继续使用原来的脚本接口
uv run --locked kernellens -w /path/to/workspace -p '读取 notes.txt' --json
```

管道输入自动使用逐行交互；显式 `--tui` 要求 stdin、stdout 都是终端。它不能与 `--prompt`、`--doctor`、`--check-api` 混用。

## 界面和按键

上方分别显示工作区、会话 ID、目标 GPU 和模型；长名称会省略显示，工作区完整路径可悬停查看或按 Ctrl+O 打开。GPU 未设置时以暖色提示。欢迎页提供三个任务入口，点击只填入命令，不直接发起请求。中间是可滚动对话，底部固定输入框与运行状态。宽窗口右侧显示决策请求、预检索、工具结果及本轮生成文件；文件选择后打开只读预览。

| 操作 | 按键或命令 |
| --- | --- |
| 发送需求 | Enter 或「发送」按钮；联想菜单中的不完整命令先补全 |
| 命令联想 | 输入 `/`，↑↓ 选择，Tab 补全，Esc 收起；也可点击候选 |
| 换行 | Ctrl+J；支持相应键序列的终端也可用 Shift+Enter |
| 粘贴代码或多行材料 | 终端自己的粘贴快捷键，粘贴后按 Enter 发送 |
| 切换控件、关闭弹窗 | Tab、Esc |
| 目标 GPU | Ctrl+G 或 `/gpu`；留空或 `/gpu clear` 清除 |
| 工作区 | Ctrl+O 或 `/workspace 路径` |
| 选择历史会话 | Ctrl+R 或 `/sessions` |
| 新会话、恢复指定会话 | `/new`、`/resume ID` |
| 收起/显示步骤栏 | Ctrl+B；窄窗口中打开完整步骤 |
| 查看运行与完整步骤 | `/runs`、`/trace [运行 ID 前缀]` |
| 浏览、预览文件 | `/files [子目录]`、`/open 相对路径` |
| 配置和帮助 | `/status`、F1 或 `/help` |
| 退出 | Ctrl+Q；空闲时也可输入 `/exit` |

`/generate 需求`、`/optimize 需求`、`/diagnose 问题` 与原 CLI 使用同一任务流程。`/history` 重新加载最近 20 条消息；会话选择器显示最近 30 个会话。文件列表最多显示 100 项，可用子目录缩小范围。

## `/` 命令联想

在输入框开头输入 `/`，即可看到全部 16 个命令及中文用途。继续输入会即时筛选，例如 `/g` 匹配 `/generate` 和 `/gpu`，`/优化` 匹配 `/optimize`。不需要模型或网络请求。

- ↑ / ↓ 切换候选；列表可滚动，所有命令都能选到。
- Tab 或鼠标点击把候选填入输入框，并留一个空格继续填写参数；焦点留在输入框。
- 不完整命令按 Enter 也会补全；已经完整输入的命令按 Enter 仍直接执行。例如 `/gpu` + Enter 打开 GPU 弹窗，`/g` + ↓ + Tab 则先填入 `/gpu `。
- Esc 收起菜单且保留输入；继续编辑后可再次显示。无联想菜单时，Tab 恢复切换控件的作用。
- 开始填写参数、粘贴多行代码、把光标移到命令中间、打开其他弹窗或运行任务时，菜单自动收起。补全不会替换已有参数或多行材料。
- 菜单显示在输入框上方，不挤动输入区，随终端窗口大小调整位置。匹配为空时显示提示，Enter/Tab 不会意外发起模型请求。

例如依次输入 `/ge`、按 Tab、填写 `生成一个 GEMM`、按 Enter，即提交生成需求。

## 输入一个要求后

以 `/generate 生成一个 FP16 GEMM，M=N=K=1024` 为例：

1. 界面接收输入，防止重复提交，在后台线程调用现有应用入口。
2. 没有目标 GPU 时，应用保存 `waiting_input`，界面显示问题；此时没有模型请求。
3. 直接回答 `NVIDIA A100 80GB`，应用在同一会话中携带原需求继续。也可以先在 GPU 弹窗设置，再输入“继续”。
4. 应用执行知识预检索、模型决策、工具操作与交付审核；真实进度事件出现在步骤栏。
5. 本轮结束后，对话区显示完整回答，状态栏显示运行状态、请求数与可用 Token 数，侧栏列出保存的候选。点击文件可查看正文，`/trace` 查看完整反馈。

界面不会判断候选已经在 GPU 上正确运行。生成、优化、诊断和证据规则由原有应用负责，详见 [Agent 原理](agent-guide.md)。

## 实现方法

入口分工是 `cli.main → KernelLensTUI → AgentApplication.run → 原有 Agent Loop`。[tui.py](../src/kernellens/tui.py) 负责界面与交互，[tui.tcss](../src/kernellens/tui.tcss) 负责布局；[tui_commands.py](../src/kernellens/tui_commands.py) 统一维护联想与帮助的命令名、用法和说明。菜单使用 [Textual OptionList](https://textual.textualize.io/widgets/option_list/) 显示筛选结果；补全仅修改输入框，执行仍交给原有命令处理。键盘事件按输入控件的队列顺序处理，确保快速粘贴和补全不会抢先提交空输入。模型协议、Prompt、检索、工具和审核均复用原实现。

Textual 的界面线程处理键盘、重绘和会话查看；每次任务使用一个后台线程执行同步模型请求。后台通过 `post_message` 发送进度和结果，界面处理消息后更新控件。模型请求不会阻塞界面事件循环。线程之间不能共用默认 SQLite 连接，因此界面和每个后台任务分别创建、关闭自己的 AgentApplication/数据库连接；它们访问同一工作区数据库。这遵循 [Textual 的线程 worker 文档](https://textual.textualize.io/guide/workers/)。

每次只允许一轮 Agent 任务。运行时可以打开步骤或文件，但不能发送第二个任务、切换工作区或修改会话 GPU。不会引入多个 Agent、服务队列或第二套持久化格式。原 CLI 创建的会话可以在 TUI 中恢复，反向亦然。

文件预览沿用 Workspace 的路径、敏感文件、符号链接、普通文件和 1 MB 限制；渲染最多保留前 100000 字符并明确标注截断。界面文本经过现有凭证脱敏和终端控制字符清理；用户文字与文件正文按字面显示。Markdown 回答不自动打开链接。预览不会执行文件。

## 当前边界

- 模型仍使用同步、非流式 HTTP 请求。步骤栏显示真实执行事件，最终回答整段出现，不模拟逐字输出。
- 运行中按 Ctrl+Q 表示“本轮完成并保存后退出”，当前任务会继续调用模型和执行工具。它不表示立即取消。需要 Ctrl+C 中断能力时，使用 `--plain`；本轮没有修改核心 Runtime 的停止机制。
- 模型、网络和输入错误会回到可继续交互的状态；不能把错误或预算耗尽显示成完成。API 费用与 GPU 验证边界与原 CLI 相同。
- 重启后用 `/resume` 恢复对话、GPU 与步骤。本轮文件列表只在本次任务结束后填充；历史产物可通过 `/files`、原回答中的路径或 `/open` 查看。
- 不是通用终端模拟器或代码编辑器。代码预览只读，没有 shell、任意 Python 执行、自动 GPU Runner 或供应商配置编辑器。

## 验证

维护者本地自动测试通过 Textual `run_test` / Pilot 操作实际界面，并接入真实 AgentApplication 与预设模型响应，覆盖 GPU 补问后交付、后台响应、重复提交保护、会话与工作区隔离、只读文件边界、脱敏、多行输入、80×24 窄窗口、错误恢复与退出保存，以及联想筛选、中文匹配、选择/补全、弹窗切换、空结果、粘贴与布局。

POSIX 伪终端测试真实启动 CLI 子进程，验证自动选择 TUI、显式 `--tui`、括号粘贴、快速命令补全、零模型请求的 GPU 补问和退出时恢复终端。另有 localhost HTTP 测试连接实际 ChatClient 与后台线程。默认测试没有调用真实模型供应商，也没有执行 GPU 候选。

完整界面测试与真实验收脚本留在维护者本地。仓库内可运行的源码、知识包及构建检查见 [验证说明](validation.md)。
